# 底层 CTP 行情与交易登录演示

[demo.py](demo.py) 直接继承 `vnpy_ctp.api.MdApi` / `TdApi`，没有经由 `MainEngine` 或 `CtpGateway`。

## 配置与运行

1. 在兼容的 Python 环境安装 `python -m pip install -e ".[ctp]"`。依赖固定到阅读过的 `vnpy_ctp 6.7.11.5`；其 API 创建方法需要流目录和仿真模式两个参数。
2. 复制 [无值配置](config.example.json) 为 `config.local.json`，填写自己的 SimNow 配置。UserID、密码、AppID、AuthCode 默认为空，原样运行会拒绝加载。不要使用公共示例账号，不要提交任何账户标识、密码和授权码。
3. 从仓库根目录运行：

```powershell
python -m projects.ctp_demo.demo --config projects\ctp_demo\config.local.json --live
```

不传 `--live` 时退出码为 2，不读取账户配置、不加载原生接口、不联网；这不是生成模拟行情的 dry-run。`--live` 仅允许联网登录，绝不启用交易。前端地址来自本地配置，程序并不验证其确属 SimNow；操作者必须核对官方当前地址，禁止配置实盘账户。

显式联网后默认前台持续运行，`Ctrl+C` 释放接口。输出每条有效行情的本地 UTC 接收时刻、合约、交易日、自然日、柜台时间、最新价、买卖价及累计成交量。缺失报价显示 `null`，无效最新价记录为 `invalid_tick`，不会伪装成正常行情。

限时现场复验：

```powershell
python -m projects.ctp_demo.demo --config projects\ctp_demo\config.local.json --live --duration 60 --startup-timeout 30 --quote-timeout 30 --events reports\runs\ctp_live_01\events.jsonl
$LASTEXITCODE
```

事件文件以独占创建模式打开，已有文件会报错。只有两个通道登录、交易认证、全部订阅成功且**每个配置合约**至少有一条有效行情，限时运行才可能成功退出。汇总记录逐合约回调数、有效数、当前连接状态和 `orders_sent=0`。订阅成功或仅一条快照不等于合约持续活跃；应检查多个交易所时间点与累计成交量变化。

## 生命周期与错误

- MD 连接 → 登录 → 逐合约订阅 → 行情。
- TD 连接 → 终端认证 → 登录；不查询账户，不自动确认结算，不发单、不撤单。
- 任一通道断线清除对应状态并立即失败退出，不自动重新登录；晚到的重连与成功回调不再改变状态。恢复需人工核验后启动新进程。主动释放接口时的断线回调不算故障。
- SDK 请求返回非零、柜台返回错误、订阅失败都会输出错误码并停止。原始响应与请求载荷不写日志，避免账号信息泄露。
- 初始就绪超时默认 30 秒；每个合约自进程启动起、以及最近一次有效 Tick 起，最长静默时间默认 60 秒。缺少行情或行情停止更新均失败退出，无效 Tick 不刷新计时。午休、非交易时段或不活跃合约也会触发该边界；调整参数必须如实记录，不能把延长超时当作活跃证明。
- 正常完成返回 0，连接/请求/行情超时/清理失败返回 1，CLI 参数错误返回 2。`Ctrl+C` 仅在已就绪且每个合约均收到有效行情后返回 0；否则返回 1。退出码 0 仍不是开平仓验收。
- UserID、密码、AuthCode 不进入配置对象的 `repr`；入口只记录异常类型和通用排查提示，不输出可能包含凭据、原始 JSON 或本地路径的异常正文。错误仍返回非零，不默认为成功。
- API 流目录在忽略的 `.ctp-flow` 中；不要并发启动多个实例共用此目录。

示例 `au2612`、`ag2612`、`cu2611`、`rb2701` 只展示跨品种订阅格式，**没有经过当日成交量排名核验**，且会到期。运行前按 SimNow 当前合约和时段选择。

## 已验证与未验证

[离线测试](../../tests/test_ctp_demo.py) 验证认证顺序、返回码、断线终止、逐合约行情超时、价格过滤、显式联网开关、配置脱敏、默认持续运行逻辑和清理流程。不使用真实账户。

本次尚未验证原生发行包可安装、真实前端可连接、回调 ABI、真实行情活跃度和长时间稳定性。不能把离线替身测试称为联网成功。
