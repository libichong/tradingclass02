# Wiki 维护规范

依据 [用户提供的 LLM Wiki 指南](sources/llm-wiki.md)，用于本项目的资料接收、问答回写和日常核对。这是可链接的项目文档，不是声明所有 Agent 都会自动加载的配置文件；维护 Wiki 时先读本页和 [索引](index.md)。

## 目录与职责

| 位置 | 内容与约束 |
|---|---|
| 本地 `raw`、原始数据、只读附件 | 原始来源不原地改写；保留版本或 SHA256，不把账户、受限原件和原始资金快照入库 |
| `wiki/sources` | 来源标题、接收日期、可追溯标识、原创摘要、版本和局限 |
| `wiki/concepts` | 跨来源综合的概念、比较和业务链路；链接依据与相关实现 |
| `wiki/code` | 本仓库实现、设计方案、验证证据和未实现边界；不把方案当成运行结果 |
| [index.md](index.md) | 分类列出每一篇知识页，并给出一句内容摘要 |
| [log.md](log.md) | 只追加的维护时间线，记录接收、问答回写和核对 |
| [README](../README.md) | 面向使用者的入口、运行命令、交付状态和安全边界 |
| [验证记录](../reports/validation.json)及实验输出 | 实际命令、环境、退出码和证据；原实验不覆盖，新实验另建目录 |

文件名采用简短的小写英文与连字符；正文沿用中文说明，引用的 API 名称保持原样。链接使用相对 Markdown 路径，避免提交本机用户目录或会话临时附件的绝对路径。

## 页面与证据约定

- 来源页区分原文事实、项目解读和待验证事项；可获得时记录上游版本/提交或文件哈希，不推测未知作者、地址和数据口径。
- 概念页引用来源，说明与其他主题及实现的关系；新增重要主题前先检查索引，避免重复建页。
- 实现页区分“设计”“已实现”“离线验证”“现场验证”；给出真实证据入口，不把别人的成绩、编译通过或模拟回调当成本次真实交易。
- 出现矛盾时标明冲突内容、来源、日期与尚待解决的问题；纠正当前说明，但不删除旧日志、失败尝试和已有实验来掩盖历史。
- 不把 Wiki 维护指南当成交易授权。安全和研究冻结要求以 [README](../README.md)、[CTP 说明](../projects/ctp_demo/README.md)及[研究说明](../projects/gap_research/README.md)为准。

## Ingest：接收一个来源

1. 确认来源身份、读取权限和版本；只读原件，记录哈希或上游提交。原件只存在会话附件时明确说明不可随克隆恢复。
2. 阅读内容，提炼与本项目相关的事实、方法、限制和冲突；缺失内容显式留空，不以推测补齐。
3. 更新或创建来源页，再修改受影响的概念/实现页与 README 状态。只更新真正相关的页面，不为凑数量扩写。
4. 在索引加入链接和一句摘要；确保新页可从索引到达，并链接相关知识页。
5. 追加接收日志；检查本地链接和受影响页面的状态一致性。

## Query：问答与回写

1. 先读索引，再读问题所需的来源、概念和实现页；Wiki 没有依据时明确缺口。
2. 回答附上依据，区分源码解释、设计假设、离线证据和现场事实。
3. 对可复用的新比较或推导，更新已有主题或新增必要页面，注明推导依据与限制；不把未验证的聊天结论写成事实。
4. 回写后更新索引并追加 `query` 日志；纯临时操作或没有新增知识的回答无需另建页。

## Lint：知识库核对

- 检查本地链接是否存在；每篇知识页是否从索引可达，是否有主题相关的交叉引用。
- 对照 README、来源页、实现页和验证记录，找过时状态与相互矛盾的能力声明。
- 检查来源追溯与证据缺口；“静态文件存在”不能作为真实行情、交易闭环或因子有效性的证据。
- 核对历史日志是否保留、新实验是否独立；不要为通过检查而删掉失败证据或解封记录。
- 追加本次检查的范围、发现、修正和未验证项。检查器通过只代表所检查的结构，不证明所有知识都正确。

## 日志格式

新记录使用 `## [YYYY-MM-DD] ingest | 标题`、`query` 或 `lint` 前缀，每条说明来源、改动、证据和遗留问题。早期日志保持原样，新记录明确更正旧状态，不回写当时尚未知晓的事实。

目前不引入额外 Wiki 插件或搜索依赖。后续若确有检索规模或自动加载需求，再与用户确认工具与配置范围。
