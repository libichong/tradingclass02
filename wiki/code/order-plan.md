# 突破价格下单方案（待审核，不执行）

**当前只实现行情和交易登录。本文不是运行配置；发单和撤单代码均未编写。**

1. **触发**：只针对确认的仿真合约；上一条有效且新鲜报价 ≤阈值、当前报价 >阈值才触发。启动第一条已高于阈值不发单；同一策略/合约/交易日只允许一次，经人工重置才能再触发。
2. **前置检查**：MD/TD 已登录，终端认证和结算确认成功，合约规格/交易时段已确认；资金、持仓、活跃订单查询完成且一致。断线、陈旧行情、未知订单状态、查询失败一律不允许新增订单。
3. **订单**：仅 1 手限价买开作为审核建议；按最小变动价位处理价格，在涨跌停内，最多允许一个价位滑点。不追价、不自动重复发单；方向、阈值、最大价格和预算必须由用户确认。
4. **状态**：`DISABLED → READY → SENDING → WORKING → PARTIAL/FILLED/CANCELED/REJECTED`。先持久化唯一触发键，再提交请求；返回 0/订单号仅代表请求阶段，不标记成交。拒单、超时和部分成交交人工处理。
5. **断线**：立即冻结新增单；重连后重新查询订单、成交、持仓、资金，根据交易日/会话/订单标识和成交 ID 对账。状态未知时不能重发。对账完成也不自动解除人工暂停。
6. **风险与证据**：只允许自己的 SimNow 账户；单日最多一次、1 手、最大名义金额和资金占用；紧急停止阻止新增单，但不宣称立即撤掉柜台订单。请求、回报、拒单和实际成交分别记录，账号信息脱敏。

## 执行前必须确认

合约、方向/开平、阈值、价格上限/滑点、手数、资金与名义金额上限、运行时段、撤单及部分成交处理。确认后再开发发单链路、补离线状态测试和可控仿真验证；当前“实现作业”不越过原题的先审核边界。
